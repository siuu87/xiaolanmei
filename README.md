# 小蓝莓 🫐

两个人的专属 AI 陪伴空间。本地优先、可多端使用（手机 + 电脑）、可自我扩展。

一个会陪你聊天、记备忘录、管待办和课表、一起做饭读书听歌、哄你睡觉，还能自己写代码的温柔陪伴者。

## 技术栈

- **前端**：React + TypeScript + Vite + Tailwind CSS + shadcn/ui + Zustand + React Router
- **后端**：Node.js + Fastify + SQLite（better-sqlite3）+ Drizzle ORM
- **AI**：OpenAI 兼容协议（可接入 DeepSeek / Qwen / o 系列等任意网关与模型）
- **原生**：Android（Kotlin + AccessibilityService，真·控手机）
- **部署**：阿里云 VPS + PWA

## 目录结构

```
小蓝莓/
├── 前端/     React 前端（Vite，端口 5173）
├── 后端/     Fastify 后端（代理 API Key、SQLite 数据库，端口 3001）
├── android/  真·控手机的原生 Android 桥（无障碍服务 + SSE 长连接）
├── docs/     说明文档（phone-control.md 等）
├── handoff/  交接说明（给外部设计/编码助手；zip 快照不入库）
├── scripts/  本地辅助脚本（start-remember-me.sh、setup-recipe-nook.bat 一键装小食谱）
└── deploy/   部署配置（Docker + Nginx）
```

## 本地运行

### 后端（端口 3001）

```bash
cd 后端
npm install
npm run dev
```

首次使用可在「设置 → 模型站子」里配置 Base URL + API Key + 模型列表。
Key 只存在后端，绝不下发前端。

可选能力（都不配也能正常聊天）：

```bash
# 后端/.env —— 情绪增量分析用的小模型（留空 = 复用主模型）
EMOTION_MODEL=
EMOTION_MAX_TOKENS=100
EMOTION_ANALYZER=on

# 后端/.env —— 心潮·念（取代 Ombre Brain；留空 = 回退本地情绪面板）
XINCHAO_URL=http://127.0.0.1:18110
XINCHAO_TOKEN=

# 后端/.env —— PaiVoice 实时语音（留空/没起 = 回退旧通话浮层）
PAIVOICE_WS_URL=ws://127.0.0.1:8780

# 后端/.env —— Ombre Brain Dashboard 记忆中枢（留空 = 内心页「记忆」标签显示未接入）
OMBRE_DASHBOARD_URL=
OMBRE_DASHBOARD_PASSWORD=
OMBRE_DASHBOARD_TIMEOUT_MS=4000
```

配好后可用 `GET /api/xinchao/status` 自检心潮；`GET /api/paivoice/status` 探 PaiVoice；
`GET /api/ombre-dashboard/status` 自检 Ombre Brain 记忆中枢（含 `/buckets` `/search` `/buckets/:id`）。

### 可选侧车：小食谱（recipe-nook）

「今天吃什么」`/food` 由 recipe-nook 提供（FastAPI，端口 8790）。

**Windows 一键脚本**（推荐，双击即可，五步全是幂等的，重复运行不会动你的饭账）：

```
scripts\setup-recipe-nook.bat            # 需要时构建菜谱库，然后启动
scripts\setup-recipe-nook.bat check      # 只体检，不启动
scripts\setup-recipe-nook.bat build      # 只构建菜谱库
scripts\setup-recipe-nook.bat rebuild    # 强制重建菜谱库
```

它依次做：建 `.venv` → 装依赖 → 生成 `.env` → 菜谱库为空时才导入 HowToCook
（约 100MB，首次几分钟；源码缓存在 `%TEMP%\recipe-nook-HowToCook`，之后重建很快）
→ 在 8790 启动。已有内容一律跳过，下载被中断也会自己清掉重下。

手动做法（macOS / Linux 或想自己控制每一步）：

```bash
cd recipe-nook
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
cp .env.example .env                      # 估热量的 LLM key 可不填
.venv/Scripts/python.exe -m uvicorn server:app --port 8790
```

菜谱库需自行构建，最小可用库用公有领域的 HowToCook（几秒入库，372 道 / 123 张图）：

```bash
git clone --depth 1 https://github.com/Anduin2017/HowToCook <你的路径>
.venv/Scripts/python.exe scripts/build_htc.py <你的路径>
```

查当前库里有多少道菜：`.venv/Scripts/python.exe scripts/count_recipes.py`（一键脚本靠它判断要不要构建）。

侧车没起时 `/food` 会显示上面这几条命令 + 「重新连接 / 先回去」，不会白屏。

> 改 `setup-recipe-nook.bat` 前先看文件头的 NOTE，其中三个坑最容易撞：
> ① 文件必须**纯 ASCII**。cmd.exe 按系统代码页读 `.bat`，UTF-8 里的中文会被解错并把命令行切碎；
> 中文说明一律放 README。② 括号块（`if/else`）里的行**不能以 `...` 结尾**，
> cmd 会预先解析两个分支，没走到的那个分支里的 `...` 也会让整个脚本报「此时不应有 ...。」而中断。
> ③ **脚本正在跑的时候别改它** —— cmd 按字节偏移续读，运行中改文件会让下一条命令
> 从不相干的行的中间开始，看起来像脚本 bug。行尾保持 CRLF（已用 `.gitattributes` 钉住 `*.bat text eol=crlf`）。

## 功能总览

结构：**聊天是常驻底座**，其余页面以整页覆盖层叠在对话上；移动端用抽屉导航，桌面端用侧边栏。
主要入口：**聊天 / together / 酒馆小手机 / 首页看板 / 礼物盒 / 游戏屋 / 我的资料 / 设置**。
（游戏屋入口在抽屉「生活小趣味」分组内。）

### 聊天
- 流式回复 + Markdown 渲染
- **多图消息**：接入 [PhotoStack](https://github.com/Wren036/PhotoStack) 的微信式堆叠照片卡
  （三张守恒 / 探边 / 跟手翻页 / 快甩），点开整页看大图
- **时间感知**：送模型前给每条消息动态渲染 `[Tue 2026-08-11 17:32:10 CST · +9h 44m]`，
  存档保持干净、重复渲染幂等；`MESSAGE_TIMESTAMPS=off` 可关
- **情绪与内心**：每轮开流前用轻量模型分析最近 4 条消息（80/20 加权）→ 四维状态机
  （占有欲与醋意 / 紧绷与情欲 / 克制与自控 / 示弱与委屈）平滑累积 → 把数值翻译成**行为策略**
  注入主模型；**内心**面板（点聊天顶栏名字 / 名字旁小红点）展示心潮的此刻与 11 股驱力
  （心潮没起时回退六条本地情绪数值）
- **心潮·念（Xinchao·Nian）**：自托管的「驱力 + 记忆」引擎。每轮开流前拉 `/v1/now`
  注入 `[心潮 · 此刻]`，流结束后把「她说 / 他回」写回 `/v1/conversation-event`；
  **心潮是独立完整页 `/xinchao`**：花瓣（11 股驱力）、念头池（单独一类）、情绪、时间线、
  小屋、内核；「内心」只留摘要卡与入口（心潮没起时回退本地情绪面板）。
- **Ombre Brain 记忆中枢（内心页「记忆」标签）**：心潮页顶部置顶导航「心潮 / 记忆」切换两个中枢视图；
  记忆标签经后端 `/api/ombre-dashboard` 代理接入 [Ombre-Brain](https://github.com/P0luz/Ombre-Brain) 的
  Dashboard（令牌只在后端，自动会话登录 + 401 重登 + 并发锁）。支持 全部 / 动态 / 永久 / 已归档 / 已钉选
  筛选与 300ms 搜索防抖，点记忆卡弹出半透明手账风 Bottom Sheet 详情（效价 / 唤醒 / 重要 / 活跃度 + 「为什么记住」）。
  `OMBRE_DASHBOARD_URL` 没配时该标签显示「记忆中枢还没接上」，不报错。
- **PaiVoice 实时语音**：实时语音协议层（AGPL-3.0）已**彻底并入 React 通话**（`PaiVoiceStage`
  组件取代原 iframe 嵌入），接通后直接在本通话浮层里渲染星空背景与实时语音，不再有独立的
  `/paivoice` 静态页。**默认完整通话页（能看实时对话），一键切可拖拽悬浮窗**
  （可收起成标题条且不断线，尺寸跟着视口算，矮屏也不会被顶出屏幕），支持打断、断线接回、
  实时字幕与静音。标题栏最右是一颗带文字的**「✕ 退出」**（Esc 在整页时也等于退出，
  悬浮窗时只收起不挂断）。PaiVoice 没起时自动回退原通话浮层。
  视频通话仍走旧浮层（PaiVoice 的画面是「给回复端看」，不是双向视频流）
  通话页（2026-11-09 按 Earshot「听着呢」教程）改成电话感：绿色「接通」按钮；**两条光线**
  （珊瑚色＝你 / 白色＝它，谁说话谁起伏）；**它说话时点一下光线就打断**（键盘 Enter / 空格同效）；
  左静音、右红色挂断；底部小字显示本轮「你说完 → 它出声」的延迟；状态文案口语化
  （「嗯，我在听」/「等等，让我想想…」/「信号有点远，我等你一下…」）；停 **0.8s** 才算把话交出去
  （VAD `endSilenceMs: 800`）。轻声回应、逐句短句朗读、「认真告别才挂」等**内容生成策略在外部 8780 核心**，
  本仓库只做 UI / VAD / 打断接线，不含模型与 ASR/TTS 实现。
- **完整的「打电话」流程**（2026-11-09）：不再是点一下就进通话，而是先「呼叫中」等对方接 ——
  他可能接（约 72%），也可能这会儿不方便不接；接了才挂出通话浮层。他也会**主动打过来**，
  任意页面弹一通**来电弹窗**（头像 / 名字 / 倒计时 / 绿色接听 · 红色拒接，Esc 算拒接），
  响 26 秒没接就是未接来电。**没接成他会在聊天里追问一句**（「刚打给你没接上，是不是在忙呀？」 /
  「刚看到你打来，那会儿没顾上接」）；接通 / 拒接 / 未接都落 `calls` 表并推一张通话卡片。
  主动来电**不是定时器**：前端已撤掉随机排程，改由模型在对话里自主决定 —— 后端注册
  `incoming_call` 内置工具，模型觉得「想听你声音 / 想安慰你」时调用，`chat/stream` 推一条
  `incoming_call` SSE 事件，前端 `onIncomingCall` 接到才弹来电卡片。刷新页面不会公式化打一通，
  一轮最多一次；已在响铃 / 通话中会被 `callSession.begin` 幂等挡掉。接真实模型后即生效。
  验收深链：`?incoming=1` 立刻弹来电；`?call=answered` / `?call=missed` 强制本次呼出结果。
- **思考链**：接入带推理能力的模型（DeepSeek-R1 / Qwen3 / o1 等）时，实时展示推理过程，可折叠
- 工具调用：联网搜索 / 读网页、长期记忆（memo）、**灵感待办池**、**开源项目关注清单**、智能编程（读写文件、跑命令、git）、**真·控手机**
- 多模态：发图识图（截图课表自动录入）、语音输入、表情包
- 树形分支：重新生成 / 编辑并重发 / 回滚 / 分支切换 / 删除
- 主抽屉（移动端）：伴侣档案（纪念日 / 双头像）· 日常生活（日历 / 心情 / 待办 / Token / 收信匣）· 模块卡 · 工具箱（插件 / 手机感知 / 工作区 / 技能 / 开源项目）

### 深夜来信（`/notes`）
- **一封慢慢读懂你的回信**（2026-11-11 改版，参考「原来 Mee 一直在慢慢读懂我｜一封冬日回信」）：
  不再是 1~3 句的温柔短信。写信前由后端 `services/letterContext.ts` 把真实素材捞出来 ——
  聊过的话、长期记忆、日记、心情、灵感待办、纪念日、节气与「认识第 N 天」——
  再由模型写成 180~320 字、5~7 段的长信：称呼「亲爱的你：」→「我记得」（一个具体小细节）
  →「我看见」（最近的状态，只描述不说教）→「我们一起」（一个马上能做的小约定）→ 落款。
  **硬性约束：只能用素材里真实出现过的事，不许杜撰**；素材不足就诚实写初识短笺。
  通话卡片 / 报错占位 / 测试消息会先被滤掉，免得把真对话挤出上下文。
  一天最多 2 封，间隔 90~180 分钟；模型站连不上时按旧约定**不写假信**，信箱保持原样。
- **一封信 = 一枚信封卡**（参考《恋与制作人》「心动邀约」）：实体信封造型，**5:3 横版长方形** ——
  背板 / 浅 V 信封口 / 可翻开的封盖 / 火漆 / 金边 / 丝带；信封撑满卡片宽度，
  日期与心境压在信封底边上；
  **未读封着、已读封盖掀开露出信纸一角**；火漆与描边跟 `letter_theme` 三套配色走
- 两列信封网格（不是横向滑动流），一眼看到一沓信
- **点信件 = 弹出一封信**（2026-11-11 重做，参考「信纸插在开口信封里」）：
  信封卡、首页/抽屉收信匣整卡都直接开新弹窗，URL 不跳；
  弹窗是**整屏纯色不透明**舞台 + 居中**固定尺寸信纸** `min(420px,86vw) × min(560px,72vh)`，
  信纸下缘插进信封，信封前面板画蓝色空心星星、左上淡蓝大引号、手写感正文与落款。
  **不管字数多少，信纸尺寸都不变**：长信只在纸上方可见区里滚动（有「继续往下读 ↓」提示），
  短信时日期/落款自动压到纸底。三种关法：右上「收起」/ 点空白 / Esc；
  `/letter/:id` 直达链接弹的是同一层。外观沿用原来的火漆信封卡（奶油手帐换皮已退回）
